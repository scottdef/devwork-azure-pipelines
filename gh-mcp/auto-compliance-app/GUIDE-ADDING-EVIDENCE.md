# Adding Evidence — Guide

How to add or update the evidence shown in the Compliance Evidence Center, by hand
and via automation.

---

## 1. How evidence works

The site is generated by `scripts/build_site.py` from two inputs:

| Input | Role |
| --- | --- |
| `CONTROLS` list in `build_site.py` (mirrors `comp-cons.md`) | **What** items exist — controls, requirements, slugs, titles |
| `evidence/<control-slug>/` source tree | **The actual evidence content** for each item |

For each evidence item the build looks for an optional source fragment and provenance
sidecar:

```
evidence/<control-slug>/<evidence-slug>.html   # body fragment — injected into the page
evidence/<control-slug>/<evidence-slug>.meta   # provenance (key: value lines)
evidence/<control-slug>/<anything-else>        # assets (images, CSVs…) copied verbatim
```

- If the `.html` fragment **exists**, the item renders as **documented** (green pill,
  counts toward "documented") with your content injected.
- If it **does not exist**, the item renders the **pending** TODO placeholder.

Generated output (in `_site/`) is **disposable** — it is rebuilt from scratch every
run and is git-ignored. **Never edit files in `_site/`**; edit the `evidence/` source
tree instead, or your changes are lost on the next build.

> The slugs (`<control-slug>`, `<evidence-slug>`) come straight from the `CONTROLS`
> list. To find them, open `scripts/build_site.py` — e.g. the MFA control is
> `multi-factor-authentication` and its first item is `all-accounts-2fa`.

## 2. Manual workflow (worked example)

This repository ships a complete, working example for the MFA item
**"All accounts have 2FA configured"**
(`evidence/multi-factor-authentication/all-accounts-2fa.*`). Reproduce it for any
other item like so.

### Step 1 — Gather the evidence
Collect whatever proves the requirement. For a GitHub setting, that is usually an API
query plus a screenshot:

```bash
gh api "/orgs/cla-org/members?filter=2fa_disabled" --jq 'length'   # => 0
gh api "/orgs/cla-org/members" --paginate --jq 'length'            # member count
```

### Step 2 — Write the body fragment
Create `evidence/<control-slug>/<evidence-slug>.html`. It is a **partial** (no
`<html>`/`<head>` — those come from the template). Use plain HTML; these CSS classes
are available for consistent styling:

| Class | Use |
| --- | --- |
| `<pre><code>…</code></pre>` | command output / raw API responses |
| `<table class="data">` | tabular data |
| `<img class="evidence" src="…">` | screenshots / diagrams |

```html
<p>All members of <code>cla-org</code> have 2FA enabled (0 without, 137 total).</p>
<pre><code>$ gh api "/orgs/cla-org/members?filter=2fa_disabled" --jq 'length'
0</code></pre>
<img class="evidence" src="2fa-org-setting.svg" alt="Require 2FA enabled">
```

### Step 3 — Add provenance (optional but recommended)
Create `evidence/<control-slug>/<evidence-slug>.meta`:

```
date: 2026-06-24
by: S. DeFranc (Security Engineering)
source: GitHub REST API — /orgs/cla-org/members?filter=2fa_disabled
status: reviewed
```

Recognized keys: **`date`**, **`by`**, **`source`**, **`status`** (lines starting with
`#` are ignored). Anything you omit shows `TODO`.

### Step 4 — Drop in assets
Put screenshots/exports in the **same control folder**
(`evidence/<control-slug>/`). The build copies every non-fragment/non-meta file into
the output and into the downloadable `.zip`, so reference them with a **relative**
path (`src="2fa-org-setting.svg"`). This keeps the evidence self-contained offline.

### Step 5 — Build and preview
```bash
make build      # regenerate _site/
make serve      # preview at http://localhost:8000
```
The item now shows a green **documented** pill, the home/control counts increment
(e.g. `1/3 documented`), and the file list marks it with ✅.

### Step 6 — Publish
Commit the `evidence/` changes and open a PR to `main` (the branch is PR-protected).
On merge, the **Deploy Evidence Center** workflow rebuilds and publishes to GitHub
Pages. See `README.md` for Pages setup.

---

## 3. Adding a brand-new control or requirement

1. Add it to `comp-cons.md` (the source of truth).
2. Mirror it in the `CONTROLS` list in `scripts/build_site.py` — add an `Evidence(...)`
   entry (or a new `Control(...)`). Pick stable `slug`s; they become URLs and zip
   names.
3. `make build`. The new item appears as **pending** until you add its fragment
   (Section 2).

## 4. Automating evidence gathering

Evidence collection is automated by **per-control collector scripts** in
`scripts/collect/`, driven by one workflow,
**`.github/workflows/collect-evidence.yml`**.

### The collector framework
- `scripts/collect/<control-slug>.sh` — one per control. Each emits its evidence
  via helpers in `scripts/collect/_lib.sh` (`emit`, `emit_manual`, `emit_asset`).
- **Two modes:**
  - **live** (default, used in CI): queries real APIs (`gh api`, Dynatrace) and
    refreshes only the **API-automatable** items, stamping `status: reviewed` (or
    `needs remediation`). Manual items are left untouched.
  - **sample** (`--sample`): writes realistic sample content for **all** items
    (`status: sample`/`manual`) and never clobbers an existing file (use `--force`
    to overwrite). This is what `make sample` runs to seed the demo evidence.
- Run one locally:
  ```bash
  scripts/collect/multi-factor-authentication.sh --sample      # safe, no API
  ORG=cla-org GH_TOKEN=$TOKEN \
    scripts/collect/multi-factor-authentication.sh --live      # real data
  ```

### The workflow
`collect-evidence.yml` runs weekly (`cron`) and on demand (`workflow_dispatch`
with a `control` selector = `all` or one slug). It runs the collector(s) in live
mode and opens **one PR** with the refreshed `evidence/`. On merge, the deploy
workflow republishes.

### Writing a collector item
In `scripts/collect/<control>.sh`, pipe an HTML body into `emit` (automatable) or
`emit_manual` (human-maintained):

```bash
source "$(dirname "${BASH_SOURCE[0]}")/_lib.sh"; parse_args "$@"; C="multi-factor-authentication"

if is_sample; then disabled=0; else disabled="$(gh_jq "/orgs/$ORG/members?filter=2fa_disabled" 'length')"; fi
emit "$C" all-accounts-2fa "Security Engineering" "GitHub REST API" \
  "$(is_sample && echo sample || echo reviewed)" <<HTML
<p>$disabled members without 2FA as of $(today).</p>
HTML
```

### What each collector pulls
| Control | Automatable (live) | Manual (sample/human-maintained) |
| --- | --- | --- |
| user-id-auditing | profile audit script + weekly run history | notifications, suspensions |
| multi-factor-authentication | `members?filter=2fa_disabled`, org 2FA setting | new-user onboarding doc |
| repository-visibility | repo visibility counts, member-create settings, scan/alert | Terraform default-visibility |
| repository-permissions | collaborator/team permission dump | — |
| dynatrace-logs-integration | Dynatrace ingest/query/retention (sample if no `DT_*`) | — |
| compensating-control-settings | `control-*.yml` results + schedule | — |
| pat-lifetime-scope | PAT policy, reminders, expired-token audit + scan | scope approvals, Terraform |
| oauth-github-app-restrictions | access policy, allowlist, audit-log monitoring | app approval register |
| ssh-keys | audit-log SSH usage, alerting rule | notify-and-remove log |

### Things to get right
- **Token scope:** the default `GITHUB_TOKEN` **cannot** read org 2FA/members/PAT
  policy or the audit log. Provide `ORG_AUDIT_TOKEN` (fine-grained PAT or GitHub App,
  `admin:org` read; audit-log read for SSH/app-install items).
- **Dynatrace:** set `DT_ENV_URL` + `DT_API_TOKEN`, or that collector emits sample.
- **PR creation setting:** enable *Settings → Actions → General → "Allow GitHub
  Actions to create and approve pull requests"*.
- **Why a PR, not a direct push:** `main` is PR-protected. The Pages deploy uploads an
  artifact (never pushes to a branch), so deployment is unaffected — and evidence still
  lands via reviewed PR, exactly the audit trail you want.
- **Keep secrets out of evidence:** write counts/settings, not tokens or raw PII.

## 5. Quick reference

```
evidence/<control-slug>/<evidence-slug>.html   body fragment (presence ⇒ "documented")
evidence/<control-slug>/<evidence-slug>.meta   date: / by: / source: / status:
evidence/<control-slug>/<file>                 asset, copied to output + zip
scripts/build_site.py  → CONTROLS              add/rename controls & items
make build | make serve | scripts/smoke_test.sh
```
