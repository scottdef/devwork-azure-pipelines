# 🗂️ Compliance Evidence Center

A pure-static, **offline-capable** evidence repository for CLA's GitHub security &
compliance program, hosted on **GitHub Pages**.

The site works like a simple file/FTP server: browse compliance **controls**, open a
control's **report**, then view or download the **evidence** behind each requirement.
Every page is self-contained (CSS inlined, no JavaScript), so individual files — and
the per-control `.zip` bundles — render correctly with no network connection.

```
Home  →  Controls  →  <control> report  →  evidence/  →  evidence doc
                                        →  Download all (.zip)
```

## How it works

The whole site is generated by one script, `scripts/build_site.py`. It holds the
control + evidence model (taken verbatim from [`comp-cons.md`](comp-cons.md)) and
writes a complete static tree to `_site/`:

```
_site/
  index.html                                  # home / control index
  controls/index.html                         # directory listing of controls
  controls/<control>/index.html               # control report
  controls/<control>/evidence/NN-<slug>.html  # one evidence doc per requirement
  controls/<control>.zip                      # downloadable offline bundle
```

Evidence documents are **templated placeholders** today — each carries the verbatim
requirement, an evidence-summary section, an artifact/screenshot placeholder, and
provenance fields (collection date, owner, source). Fill these in with real evidence
over time.

## Quick start

```bash
make build     # generate _site/
make serve     # build + serve at http://localhost:8000
make sample    # seed/refresh sample evidence for all controls
make clean     # remove _site/
```

Requires only Python 3 (standard library) — no dependencies to install.

## Deployment (GitHub Pages)

`deploy-site.yml` builds the site and publishes `_site/` via the official GitHub
Pages deployment. To enable:

1. **Settings → Pages → Source:** select **GitHub Actions**.
2. Push to `main` (or run the **Deploy Evidence Center** workflow manually).

No `gh-pages` branch is used.

## Adding or editing evidence

Real evidence content lives in the `evidence/` source tree (not in generated
`_site/`). For each item, drop an HTML body fragment at
`evidence/<control-slug>/<evidence-slug>.html` (plus an optional `.meta` provenance
file and any screenshot/data assets); the build injects it and marks the item
**documented**. To change *which* items exist, edit [`comp-cons.md`](comp-cons.md)
and mirror it in the `CONTROLS` list in `scripts/build_site.py`.

See **[`GUIDE-ADDING-EVIDENCE.md`](GUIDE-ADDING-EVIDENCE.md)** for the full manual and
automated workflows (there's a worked MFA example and an example collection workflow,
`collect-mfa-evidence.yml`). Then `make build` and review with `make serve`.

## Controls covered

Defined in [`comp-cons.md`](comp-cons.md):

- User ID & Profile Standards Auditing
- Multi-Factor Authentication
- Repository Visibility
- Repository Permissions
- Dynatrace Logs Integration
- Audit Compensating Control Settings
- PAT Lifetime & Scope
- OAuth App & GitHub App Restrictions
- SSH Keys

## Automated evidence collection

Per-control collector scripts in `scripts/collect/` gather evidence from real APIs
(`gh api`, Dynatrace) and write it into the `evidence/` tree. The
`collect-evidence.yml` workflow runs them weekly (or on demand, per control) and
opens a PR with the refresh. Locally, `make sample` runs every collector in
`--sample` mode to seed realistic sample evidence (all 9 controls render fully
documented out of the box). See
[`GUIDE-ADDING-EVIDENCE.md`](GUIDE-ADDING-EVIDENCE.md) §4.

The `control-*.yml` workflows are separate standalone compliance checks (org
settings, repo visibility, rulesets, custom roles) that pass/fail on a cron and feed
the compensating-controls evidence.
