# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Compliance Evidence Center** — a pure-static, no-JavaScript site hosted on GitHub Pages that presents compliance evidence as a browsable, FTP/Apache-style directory. Each compliance control (defined in `comp-cons.md`) is a folder; each required piece of evidence is a self-contained HTML document that can be viewed on the site or downloaded for offline use. Per-control `.zip` bundles let auditors grab a complete control's evidence in one download.

The entire site is generated by one Python script — there is no runtime server, framework, or package manager.

## Architecture

### Single-generator model
`scripts/build_site.py` is the whole build. It holds the control/evidence data model (the `CONTROLS` list, derived verbatim from `comp-cons.md`) and emits the complete static tree into `_site/`:

```
_site/
  index.html                                  home / control index
  controls/index.html                         directory listing of all controls
  controls/<control>/index.html               control "report" (lists evidence items, links zip)
  controls/<control>/evidence/index.html      directory listing of evidence files
  controls/<control>/evidence/NN-<slug>.html  one templated evidence doc per requirement
  controls/<control>.zip                       downloadable bundle of the control folder
  .nojekyll                                    disables Jekyll so files serve verbatim
```

### Key invariants
- **Everything is self-contained.** CSS is inlined into every page (the `CSS` constant in `build_site.py`) so any single HTML file, or any extracted `.zip`, renders correctly with zero network access. Do not introduce external stylesheets, scripts, or CDN links — that breaks offline use.
- **Pure static, no JavaScript.** Browsing works via pre-generated directory-listing pages and relative links. Keep it that way.
- **Relative links only**, computed by depth (e.g. an evidence doc links home via `../../../index.html`). If you change the directory depth of any page, fix its `crumbs(...)` and link paths accordingly.
- **`comp-cons.md` is the source of truth** for which controls/evidence items exist. To add or change which items exist, edit the `CONTROLS` list in `build_site.py` to match `comp-cons.md`, then rebuild.
- **Real evidence content lives in the `evidence/` source tree, never in `_site/`.** For each item the build injects `evidence/<control-slug>/<evidence-slug>.html` (a body fragment) plus an optional `.meta` provenance sidecar (`date`/`by`/`source`/`status`), and copies any sibling asset files into the output and the per-control zip. If the fragment is absent the item renders the **pending** TODO placeholder; if present it renders **documented** (green pill, counts toward the documented totals shown on the home/control pages). `_site/` is regenerated from scratch every build — editing it directly is pointless. Full instructions: `GUIDE-ADDING-EVIDENCE.md`.

### Deployment
`deploy-site.yml` (a GitHub Actions workflow) runs `build_site.py` and publishes `_site/` using the official GitHub Pages deployment (`upload-pages-artifact` + `deploy-pages`). No `gh-pages` branch — Pages must be set to "GitHub Actions" as the source. Triggers on push to `main` (when the script/`comp-cons.md`/workflow change) and `workflow_dispatch`.

### Evidence collection
`scripts/collect/` holds one collector per control plus shared `_lib.sh` (`emit` / `emit_manual` / `emit_asset` helpers). Collectors run in **live** mode (query `gh api`/Dynatrace, refresh only API-automatable items, `status: reviewed`) or **sample** mode (`--sample`: write realistic sample content for all items, `status: sample`/`manual`, never clobbering existing files). `make sample` seeds all of them; the `collect-evidence.yml` workflow runs them live (weekly + `workflow_dispatch` control selector) and opens one PR. The pill on each evidence page is driven by the `status` meta field (`sample` amber, `manual` blue, else green).

## Repository layout

Workflows live under `.github/workflows/` (`deploy-site.yml`, `collect-evidence.yml`, and the `control-*.yml` checks) — GitHub only runs them from there. Their internal paths (`scripts/build_site.py`, `evidence/...`) are repo-root-relative, which matches the checkout. Note `DIRECTORY-STRUCTURE.txt` and several `*.md` docs describe an older flat/template layout — they are historical.

The older `*.md` docs (`README.md`, `ARCHITECTURE.md`, `DEPLOYMENT*.md`, `PROJECT-SUMMARY.md`, etc.) describe a **previous** design — an hourly "trust center" status dashboard that queried the Actions API. That dashboard has been removed (its files — `index.html`, `style.css`, `status.js`, `generate-trust-center.sh`, `update-trust-center.yml` — are gone). Treat those docs as historical; this file plus `build_site.py` are current.

## Secondary: automated compliance checks

The `control-*.yml` workflows (org settings, repo visibility, repo rulesets, custom roles) are independent automated checks that run on a cron and pass/fail using `gh api`. They are *not* wired into the site build — they are standalone compliance automation that can serve as a source for real evidence (e.g. snapshotting a passing run into an evidence doc). Keep them; they map to several requirements in `comp-cons.md`.

## Common commands

No build tooling beyond Python 3 standard library. Everything runs through the `Makefile`:

```bash
make build        # python3 scripts/build_site.py --out _site
make serve        # build, then serve _site/ at localhost:8000
make clean        # remove _site/
make run-controls # trigger the control-*.yml check workflows (needs gh CLI + auth)
make status       # gh run list --limit 10
```

To build directly: `python3 scripts/build_site.py [--out DIR]`. There is no test suite or linter.

## When modifying

- **Add/change which control or evidence item exists:** edit `comp-cons.md`, then mirror it in the `CONTROLS` list in `build_site.py`. Slugs become URL/zip names — keep them stable.
- **Add/update actual evidence content:** add `evidence/<control-slug>/<evidence-slug>.html` (+ optional `.meta` and assets) by hand, or via a `scripts/collect/<control>.sh` collector — see `GUIDE-ADDING-EVIDENCE.md`. The curated example is `evidence/multi-factor-authentication/all-accounts-2fa.*` (`status: reviewed`); the rest are sample-seeded by `make sample`.
- **Change styling:** edit the `CSS` constant only (it is inlined everywhere); rebuild to propagate. Fragments may use `pre`, `table.data`, and `img.evidence`.
- **Change page structure:** the renderers are `page()`, `crumbs()`, `listing_table()`/`listing_row()`, and `render_evidence()`; source loading is `load_evidence_source()`/`parse_meta()`/`ev_documented()`. Preserve self-containment and relative-link depth.
