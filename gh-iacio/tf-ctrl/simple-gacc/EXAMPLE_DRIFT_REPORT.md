### 🔧 Manual Remediation Required

1. **Review the error output above**
   - Error indicates token lacks required permissions
   - Current token may only have `read:org` scope

2. **Fix the token permissions**:
   ```bash
   # Generate new token at: https://github.com/settings/tokens/new
   # Required scopes:
   #   - admin:org (full control of organizations)
   #   - repo (full control of repositories)
   
   # Update repository secret:
   # Settings → Secrets → GH_ORG_ADMIN_TOKEN → Update
   ```

3. **Run locally for immediate fix**:
   ```bash
   export GITHUB_TOKEN="new-token-with-correct-permissions"
   export GITHUB_OWNER="acme-corp"
   make plan
   make apply
   ```

4. **Re-run workflow after fixing**:
   ```bash
   gh workflow run drift-detection.yml
   ```

### 🔍 Common Failure Causes

| Error | Cause | Fix |
|-------|-------|-----|
| 403 Forbidden | Token lacks `admin:org` | Update token scopes |
| 404 Not Found | Wrong org name or token expired | Verify GITHUB_OWNER |
| 429 Too Many Requests | Rate limit exceeded | Wait 1 hour or use different token |
| Connection timeout | Network/GitHub issues | Re-run workflow |
| Invalid configuration | Terraform validation error | Fix terraform.tfvars |

## Real-World Example

Here's what an actual production drift detection might look like:

### Scenario
Someone manually changed organization settings via GitHub UI at 2 PM:
- Enabled repository creation for members (convenience)
- Changed default permission to "write" (quick fix for someone)
- Disabled secret scanning (thought it was causing false positives)

### Timeline

**2:00 PM** - Manual changes made in GitHub UI

**3:00 PM** - Drift detection workflow runs
- terraform plan detects changes
- Issue #42 created: "🚨 Organization Settings Drift Detected"
- Plan output shows 3 changed settings

**3:00:30 PM** - Auto-remediation completes
- terraform apply reverts changes
- Comment added to Issue #42 with success status
- Settings restored to Terraform configuration

**3:05 PM** - Platform team reviews Issue #42
- Sees what changed and why
- Identifies who made manual changes (check audit log)
- Educates team member about IaC workflow
- Closes issue as resolved

**Result**: Drift caught and fixed in 30 seconds, full audit trail preserved.
