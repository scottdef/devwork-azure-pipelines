                            QUICK START GUIDE

═══════════════════════════════════════════════════════════════════════════

┌───────────────────────────────────────────────────────────────────────┐
│ STEP 1: Setup Files                                                   │
└───────────────────────────────────────────────────────────────────────┘

  $ cp organization.tf terraform/
  $ cp organization_variables.tf terraform/
  $ chmod +x import-org-settings.sh

┌───────────────────────────────────────────────────────────────────────┐
│ STEP 2: Import Existing Settings                                      │
└───────────────────────────────────────────────────────────────────────┘

  $ ./import-org-settings.sh your-org-name

┌───────────────────────────────────────────────────────────────────────┐
│ STEP 3: Review and Adjust                                             │
└───────────────────────────────────────────────────────────────────────┘

  $ cd terraform
  $ terraform plan
  $ vim organization.tf        # Adjust to match your needs
  $ terraform plan             # Review again

┌───────────────────────────────────────────────────────────────────────┐
│ STEP 4: Apply Changes                                                 │
└───────────────────────────────────────────────────────────────────────┘

  $ terraform apply

                            USAGE PATTERNS

═══════════════════════════════════════════════════════════════════════════

┌───────────────────────────────────────────────────────────────────────┐
│ PATTERN 1: Quick Setup for Individual Developer                       │
└───────────────────────────────────────────────────────────────────────┘

  1. Read README.md (5 minutes)
  2. Run ./import-org-settings.sh your-org
  3. Edit terraform/organization.tf
  4. terraform plan && terraform apply

  Time investment: 15-20 minutes
  Best for: Single-person shops, small teams

┌───────────────────────────────────────────────────────────────────────┐
│ PATTERN 2: Enterprise Integration                                     │
└───────────────────────────────────────────────────────────────────────┘

  1. Review all documentation
  2. Run ./end-to-end-example.sh for learning
  3. Add Makefile.org to existing Makefile
  4. Install org-settings-workflow.yml
  5. Configure remote state backend
  6. Import settings via Make
  7. Create PR for review
  8. Merge to apply

  Time investment: 2-3 hours (including review)
  Best for: Teams, enterprises, compliance needs

┌───────────────────────────────────────────────────────────────────────┐
│ PATTERN 3: Continuous Management                                      │
└───────────────────────────────────────────────────────────────────────┘

  Daily workflow:
  1. Edit organization.tf
  2. make plan-org
  3. Review changes
  4. make apply-org (or commit for PR review)

  Use QUICK_REFERENCE.txt as daily reference
  Best for: Ongoing infrastructure management

                         PHILOSOPHY & PRINCIPLES

═══════════════════════════════════════════════════════════════════════════

This package embodies the Unix philosophy as practiced by Rob Pike and Ken
Thompson at Bell Labs:

  1. Make each program do one thing well
     → Each script, each file has a singular, focused purpose

  2. Expect the output of every program to become the input to another
     → Composable through pipes, Make, and workflows

  3. Design and build software to be tried early
     → end-to-end-example.sh lets you experiment safely

  4. Use tools in preference to unskilled help to lighten a programming task
     → Automation over manual processes

  5. Write programs that work together
     → Terraform + GitHub API + Make + Actions = Seamless workflow

                              MANIFESTO

  We believe infrastructure should be:
    • Declarative    - Describe what you want, not how
    • Version-controlled - All changes tracked in git
    • Reviewed      - PRs for infrastructure changes
    • Tested        - Plan before apply
    • Automated     - CI/CD for infrastructure
    • Secure        - Security by default
    • Simple        - Easy to understand and modify
    • Composable    - Build complex from simple parts

  This package delivers on these principles.
